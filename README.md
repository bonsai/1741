# 1919 — 自治体・地域通信簿

全国の自治体・行政区・地域単位と、地域文化を支える多様な主体・活動を共通の識別情報で管理し、分野別・総合評価へ接続するデータ基盤です。

## 基本方針

- 自治体マスターの母集団は、公的な自治体コード資料から作る
- e-Statの標準地域コード（5桁）と、全国地方公共団体コード（6桁）は別フィールドとして保持する
- 自治体名だけで同一性を判定しない
- 公式サイトURLは候補・確認済みを分離し、推測で補完しない
- 基準日と出典を各データに記録し、廃置分合の履歴を残す
- 政令指定都市の行政区は基礎自治体マスターに混ぜず、別階層で管理する。東京都の特別区は対象に含める
- 登録対象は広く網羅し、評価対象・評価単位は評価設計で明示する
- 地域文化は自治体に従属させず、文化資源・ステークホルダー・関係・活動を独立して記録する
- 自治体は地域文化の保護・活用に関わる多様な主体の一つとして扱う。保存会、演者、住民、学校、大学、観光協会、企業、NPO等を同じモデルで記録する

## データ構成

- `data/municipalities.jsonl`: 自治体マスター（検証後に生成）
- `data/municipality_sites_candidates.jsonl`: J-LISから収集した公式サイト候補
- `data/stakeholders.jsonl`: 地域文化に関わる主体（自治体・保存会・演者・学校・大学・観光協会・企業等）
- `data/cultural_resources.jsonl`: 民謡・民舞・祭り・伝統行事等の文化資源
- `data/cultural_relations.jsonl`: 主体・文化資源・地域の多対多関係と役割
- `data/cultural_activities.jsonl`: 保存・継承・教育・公演・観光・発信等の活動
- `assessments/cultural_assessments.jsonl`: 文化資源・主体・活動の評価記録（初期状態は空）
- `assessments/policy_assessments.jsonl`: 行政主体の文化政策・事業評価記録（初期状態は空）
- `sources/sources.jsonl`: データソース台帳
- `schemas/`: 共通レコード・指標・観測値のJSON Schema
- `indicators/`: 統計・地域指標、文化エコシステム、文化行政の評価軸カタログ
- `observations/observations.jsonl`: 収集した統計観測値（初期状態は空）
- `records/`: 自治体・文化資源・団体・イベント等の個別レコード
- `frameworks/`: 評価フレームワークとエンティティモデル
- `research/methodology.md`: 母集団・コード・履歴・文化エコシステム・指標分析の扱い

調査・分析テーマは `topics/{topic_id}/` ごとにディレクトリを分ける。トピック固有の定義、データソース、Python収集・加工コード、ノートブック、分析結果をまとめ、共通データ基盤は複製せず参照する。

- `topics/library/`: 公共図書館。図書館費・資料費ランキング、施設・利用実績、和歌山市の重点調査
- `topics/cultural-ecosystem/`: 地域文化エコシステム

- `topics/birth-dynamics/`: 出生動態

各トピックの標準構成と運用方針は `topics/README.md` を参照。

## 個別レコード（Markdown先行運用）

- `records/municipalities/{municipality_id}/README.md`: 自治体ごとの基本情報・調査項目
- `records/cultural-resources/{resource_id}/README.md`: 文化資源ごとの基本情報・関連レコード
- `records/cultural-resources/{resource_id}/survey.md`: サーベイ・調査ログ・評価領域別の確認状況
- `records/cultural-resources/{resource_id}/translations/`: 現代語訳・翻案・多言語訳
- `records/organizations/{organization_id}/`: 保存会・演奏団体・NPO・企業等
- `records/committees/{committee_id}/`: 実行委員会等
- `records/events/{event_id}/`: イベントシリーズ・開催回
- `records/people/{person_id}/`: 作者・伝承者・演者等（公開方針に配慮）
- `records/places/{place_id}/`: 会場・文化施設・記念物等
- `records/activities/{activity_id}/`: 保存・教育・記録等の活動

初期登録と調査の蓄積はMarkdownを正本として開始する。項目・ID・関係モデルが安定した段階で、必要な情報をJSONLへ構造化する。MarkdownとJSONLの二重管理を避けるため、移行時にはどちらを正本とするか明記する。フォルダ名には不変のレコードIDを使い、名称変更があってもパスを変えない。

## 文化エンティティと可視化

曲・文化資源、団体、実行委員会、イベント、自治体、個人、場所、活動を独立IDで管理し、多対多の関係で接続する。ひとつの団体が複数の曲を扱い、ひとつのイベントに複数の団体・曲が参加し、ひとつの委員会が複数のイベントを運営できる。新民謡・Neo民謡・翻案も文化資源として登録し、原曲・派生作品の関係を記録する。詳細は `frameworks/cultural_entity_model.md` と `visualizations/cultural-ecosystem.md` を参照。

## 文化行政評価基盤

1919は地域文化エコシステムの記録を土台に、文化行政の政策・投入・実施・到達・成果を検証する評価基盤を目指す。文化行政のガバナンス、予算・人材、保存継承、文化参加・アクセス、創造・発表、観光・地域経済、デジタル記録、多主体協働、政策評価・改善を評価領域とする。行政の寄与と地域主体の活動を区別し、未確認をゼロ点にせず、地域条件と出典・対象期間・評価方法を明示する。詳細は frameworks/cultural_administration.md を参照。

## 文化エコシステムの設計

文化資源を中心に置き、関係する主体を対等に記録します。自治体を文化資源の親レコードや唯一の保護者として扱いません。一つの文化資源に複数の主体・地域が関係し、一つの主体が複数の文化資源に関わる多対多構造です。

関係の例：発祥地、伝承地、保存、演者・出演、開催、資金提供、行政支援、教育、研究、記録、観光振興、広報、参加、会場提供。関係ごとに役割・期間・確認状態・出典を記録します。自治体と関係が確認できない文化資源も、文化資源として登録できます。

文化資源そのものの歴史・特徴と、主体による保存・継承・活用の活動、自治体等の支援実績は分けて扱います。指定・登録の有無だけで文化的価値を決めず、UNESCO無形文化遺産、国・都道府県・市町村指定、指定のない地域伝承を区別して記録します。

## 公式サイト候補の収集

Google Colabで `notebooks/01_collect_official_sites.ipynb` を実行します。J-LIS「全国自治体マップ検索」から都道府県ページと自治体リンクを収集します。

収集結果は候補データです。J-LISの掲載情報は更新日が古い場合があるため、自治体コード照合と現行URL確認が済むまで確定マスターに反映しません。

## コード体系の注意

e-Statの市区町村検索で使われる標準地域コードは5桁です。一方、全国地方公共団体コードは検査数字を含む6桁です。両者を混同せず、別々のフィールドとして保存します。コードの変換を推測で行わず、公的な対応資料で照合します。

## Scope

基礎自治体に加え、政令指定都市の行政区、郡、支庁・振興局などの地域単位も登録対象として扱います。東京都の特別区は基礎自治体として含めます。地域単位の種別・親子関係・評価対象かどうかを分けて管理し、自治体数や地域数は固定値にせず、基準日ごとの公的資料から算出します。

## 実践編：4テーマ

初期分析テーマは、公共図書館、地域文化、外国籍住民比率、出生動態の4つとする。指標定義は `indicators/indicators.jsonl` と `indicators/cultural_indicators.jsonl`、実測値は `observations/observations.jsonl` 等に分ける。観測値には地域ID・対象期間・単位・出典・確認状態を付ける。統計値と政策評価点は混在させない。

- **図書館**：館数、人口千人あたり蔵書数、人口一人あたり貸出冊数。
- **地域文化**：文化資源と多様な主体の関係、保存・継承、公的支援、観光活用、教育・発信を根拠付きで調査する。
- **外国籍住民**：住民基本台帳の外国人住民数・総人口・外国籍住民比率。
- **出生動態**：出生数、人口千人あたり普通出生率、合計特殊出生率。普通出生率と合計特殊出生率は別指標として扱う。

初期指標はすべて候補（candidate）であり、実データ取得・定義照合・検証を経て有効化する。
